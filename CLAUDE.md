# Quran Offline: rules for Claude Code

Offline-first Quran app by Tursina Labs. Flutter, Riverpod, Drift, Material 3.
Package: `com.tursinalabs.quranoffline`. Default branch: `main`.

Also follow the scoped rules in `.cursor/rules/` (AI search, Android R8, edge-to-edge).

## Mushaf rendering
- Mushaf uses QPC V2 per-page fonts (604 pages) and the QUL `SurahNameV2` font for surah names. Fonts load per page, so anything that rasterizes a page (snapshots, goldens) must wait for that page's font.
- Phone and Fold cover (window width < 600dp): Mushaf must stay pixel-identical to the current goldens unless I explicitly approve a change.
- Framed mode = width >= 600dp: two-page spread, or one wide single page. Odd page on the RIGHT, even page on the LEFT (1|2, 3|4 ... 603|604).
- Every page is a strict 15-row grid. Pages 1 and 2 have 8 rows and use one shared opening scale.
- Framed focus mode hides the AppBar and system bars (an approved exception to the edge-to-edge rule). Never let a design change shrink the ayah font size; report before/after sizes.

## Colors and copy
- Surah names, end-caps, page numbers, and other structure use `colorScheme.primary`. Quran text uses the ink color (`onSurface`). No hard-coded hex; use theme tokens (light, dark, and sepia must all work).
- Indonesian UI copy uses "kamu", never "Anda".
- Localized strings live in `lib/core/utils/app_localizations.dart` (id, en, zh, ja). There are no ARB files.

## Workflow
- Work on a feature branch from `main`. Small commits. Open a PR and stop for my OK; never merge without it.
- PR descriptions on GitHub must not contain a "🤖 Generated with Claude Code" line or any other "Generated by/with Claude Code" footer or session link.
- Run `flutter analyze` and `flutter test` before reporting. `scripts/qo.sh` (local, not in git) has `verify` and `apk` helpers when present.
- Never touch `feat/hafalan-setoran`. Never upload anything to Play Console. Never bump the version unless asked.
- Release builds are signed with the upload key; Play-installed builds may not update from a local build. Don't uninstall apps on the test devices.

## Versioning and What's new
- A feature/enhancement release bumps the minor version (1.2.x -> 1.3.0); a fix-only release bumps the patch (1.3.0 -> 1.3.1).
- Release builds pass `--dart-define=APP_VERSION=<versionName>` (pubspec `version:` without `+build`). Without it (debug, `flutter run`, tests) the Beranda What's new card never shows.
- The card shows once per feature version (major.minor) to upgraders; new installs save the current version as seen at onboarding.
- Play release notes live in `docs/store/whatsnew/whatsnew-<locale>` (id, en-US, zh-CN, ja-JP): plain text, one `- ` line per point, max 500 characters, this release's changes only (fix releases list their fixes too).
- Feature release (x.y.0): replace `AppLocalizations.getWhatsNewNotes` (max 3 short notes) so the `id` list equals `whatsnew-id` lines; `test/whats_new_test.dart` checks it. Fix release: leave the card notes unchanged.

## Device verification
- Test devices: Pixel 8 Pro and Galaxy Z Fold 8. Fold 8 inner screen is about 933x704dp landscape; cover about 475x751dp. Device IDs and connection details are not kept in this repo.
- Two apps live side by side on both devices:
  - **DEV app** (`com.tursinalabs.quranoffline.dev`, built with `QO_APP_ID_SUFFIX=.dev`, label "Quran Offline DEV", launcher icon with a "DEV" badge). Use it for ALL development and feature testing on the Pixel and the Fold. It can be installed, reinstalled, or cleared freely.
  - **Main app** (`com.tursinalabs.quranoffline`). Keep it installed at all times; it holds real user data. Touch it only for a release smoke test: update it with the release APK via `adb install -r` (keeps data), never uninstall it or clear its data.
- Release builds must never carry the DEV label, icon badge, or suffix; verify the release merged manifest.
- For any UI change, install a DEV build, capture screenshots with `adb exec-out screencap -p`, LOOK at them yourself, and iterate until they match the spec before reporting.
- Keep the screen awake while capturing (`adb shell svc power stayon true`), and restore it afterwards.
